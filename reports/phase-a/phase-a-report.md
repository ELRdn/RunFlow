## 3. 科学的等価性

契約テスト（tests/test_phase_a.py、27 件）で固定した内容:

- キャッシュの有無で source／candidate の投影面積と IoU が一致する。
- 3 面を並列実行した結果と直列実行の結果が面積・IoU で一致する。
- 1 面でも失敗すれば最終監査は incomplete のままになる。
- 権威成果物の検証は complete、3 面の完全一致、有限で正の面積、IoU の範囲、
  面ごとの軸を要求する。破損・欠落・ハッシュ不一致の merged は拒否する。
- cycle_family は 4 ランクと 16 ランクで一致し、速度や格子を変えると変化する。
- 実行専用でないキーの override は拒否する。
- 集約は家族不一致を拒否する。実際に frame 0 と frame 1 の混在を拒否し、家族定義の
  欠陥を検出した。
- フレーム固有の修復来歴は家族を分けず、形状パイプラインの値は家族を分ける。
- 並列ワーカーで計算した frame 0 の抗力は、単独実行の同一ランク数と完全に一致した
  （88.7838701710444 N）。

未取得の証拠: ランク数の数値独立（A6 step 1）と 3 面並列の実測短縮。どちらも
実計算が必要で、投影グリッド A/B がホストを占有している間は実行しない（同時
実行は A1 の時間比較を汚染するため）。受け入れ基準は既存の mean_drag_relative
1e-2 とセル数完全一致のみを使い、新しい緩和は導入していない。

## 5. Phase B の推奨

A1 の計測結果が分岐を決めた。**精度グリッドは原因ではなかった**（1e-7 は
1e-9 より 4% 遅い）。投影コストは解像度ではなく約 1,900 万三角形の GEOS
オーバーレイそのものなので、グリッドを粗くしても縮まない。したがって
推奨は次のとおり。

1. 1e-9 を維持し、監査スキーマ v2 は導入しない。代わりに 3 面並列（1.99x）と
   source キャッシュ（再監査で 3.85x）を常用にする。監査の再実行は約 2,500 s
   から 600 s 級へ落ちる見込みで、これが最大のレバーである。
2. 次点は修復ループの反復削減（frame-03 は 43 試行で wall 7.3 時間）。監査 1 回が
   約 10 分に縮むため、修復候補を多く試す戦略のコストが下がる。
3. 並列ランナーは A7 の有界ゲート（2 フレーム、2 ワーカー、kill と再開）を通して
   から 16/32 姿勢のサンプリング検証へ進む。
4. CPU クラウドバーストは、削減後の総計算が数コア時間規模に留まるため優先度は
   低い。形状の持ち出しは方針上、別途明示判断が必要。
